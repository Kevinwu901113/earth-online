# Agent 输出约束与意图处理

正式应用和独立工作台共用 `src/structured-harness.js`，业务类型仍各自使用运行时 Zod Schema。部署时必须保留整个仓库目录，工作台通过相对路径引用共享模块。

## 输出流程

1. 应用计算本轮意图、引用目标、预算与必要的澄清，再构建有权限过滤的检索快照。
2. 每种任务附上自己的 JSON Schema，模型只能提交对应结构。正式应用的 `chat`、`route`、`skills`、`assessment`、`review` 分开校验。
3. 必须先确认 SDK 返回 `turn/end: completed`，才能解析 JSON。空输出、截断、取消、未知结束原因均不当作成功。
4. 完整 JSON 通过 Zod 后，检查引用白名单、用户意图、时间预算与树增量。拒绝含糊删除、无效目标 ID、凭空来源、改写目标与超过预算的行动块。
5. 只有这些检查通过，才把结果交给数据库事务；执行提案仍须用户确认。数据库结算继续校验最新版本，防止生成过程中用户已修改或删除目标。

格式或意图校验失败允许在**同一总超时预算内最多 3 次生成**，每次使用独立 SDK 运行环境，原始用户请求、知识快照和 Schema 不变。反馈只有固定错误类别、Schema 字段路径和类型等信息，不把失败原文或供应商异常正文写入日志。取消、超时、输出截断、空响应、来源错误与调用错误不作为格式纠错重试。

正式应用从领取任务后计算总截止时间，检索、模型准备、生成与校验共用剩余预算；迟到或取消的结果不能提交。工作台原有的语义纠错与内层格式纠错共享 3 次实际生成额度，总耗时预算为 120 秒，避免两层各重试 3 次造成 9 次调用。SDK 退出清理另有最多 4 秒宽限，清理失败不能启动替代运行环境。输入已保存时，额度耗尽后保留脱敏失败信息供手动重试。

DeepSeek 的 JSON mode 和严格工具参数属于特定 API 路径的能力。[官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode) 与 [Function Calling 文档](https://api-docs.deepseek.com/guides/function_calling) 不能直接套用为当前 DSH Messages SDK 的不存在参数。当前 [DSH Messages 支持表](https://api-docs.deepseek.com/guides/anthropic_api/)与已安装 SDK 未暴露最终输出 Schema 参数。[Responses API](https://api-docs.deepseek.com/api/create-response/) 的原生 `text.format=json_schema` 是另一条链路；本次没有迁移供应商传输。当前实现是可实际运行的应用层校验及纠错；它不声称提供 token 解码阶段的硬性 Schema 保证，也不能保证每次模型生成都会成功。

## 意图与对话上下文

`src/intent.js` 输出有 Schema 的意图上下文：规划、时间调整、目标变更、复盘、解释、情况补充、问候和澄清。模型继续理解用户的自然语言，应用用可检查的规则提供边界：

- 同一句里分别判断肯定和否定请求，例如“不要删除目标，帮我安排今晚”。引用示例里的命令不当作实际操作。
- 以本轮输入和最近用户原话构建检索；“按上面的情况继续”包含早先目标，“重试”回到原请求，新目标重置无关预算。
- 多个目标都可能对应“这个”时先澄清，不能猜 ID；目标和事件 ID 只能来自当前用户的真实状态。
- 识别“半小时”“四十五分钟”和“不是30而是45分钟”；分步骤的10分钟、5分钟不直接当成一天预算。
- 明确延长、缩短或取消已有事件时保留正常操作；同日新增的多项时间块提案合计检查预算，不只分别检查每块。
- 从目标按钮触发的路线和技能任务采用该目标的预算与身份，不被无关聊天的否定或时间说法覆盖。
- 明确规划请求必须给行动块，或用交互问题澄清必要条件。普通问候和解释不强行创建目标，也不消耗工作台的五轮收集额度。
- 目标、基础与时间已经齐全且用户要求规划时可以提前结束收集，不为了凑五轮反复追问。

这层规则不是通用语义分类器；长句、省略和复杂指代仍可能需要模型理解及用户澄清。当前置信度是规则强度标记，不是校准过的概率。案例回归覆盖否定、指代、时间修正、新目标、重试与操作边界；真实模型效果仍需持续增加案例评测。

## 可查看的 Schema 与验证

用户展示文字遵循 `src/planning-language.js`：路线、回复与任务仅说明行动及影响练习的真实条件。工具不可用、空标准字段和检索/认证治理规则保留在内部上下文，不要求模型复述到 `summary` 或 `assumptions`；缺少练习材料时改用具体准备动作或问题，真实来源与能力评估规则继续校验。

已有路线和聊天通过 `public/planning-copy.js` 在移动端及高级界面过滤已知内部诊断。过滤仅用于展示，不重写用户输入、已保存路线、完成标准、提案命令或成果证据；实际材料提示保留。

`npm run contracts` 从运行时 Schema 导出 `docs/contracts/*.schema.json`，避免手写两份契约漂移。工作台自己的公开契约仍由 `tools/agent-workbench/export-contracts.js` 生成。

```sh
npm test
npm run test:integration
npm run check
node --test tools/agent-workbench/test/*.test.js
```

数据库集成测试仅允许独立的 `*_test` 数据库。SDK 集成测试使用本地固定供应商响应，验证非法 JSON 后的完整恢复、重复失败、取消、超时和不完整结束，无需真实模型密钥。
