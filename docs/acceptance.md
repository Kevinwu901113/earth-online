本实现依据仓库既有项目方向、最新版前端和讨论中的 14 组能力边界。功能详细需求 v0.1 完整原文尚未导入；这里记录实际覆盖，不把推测写成已确认需求。

| 讨论范围 | 实现 | 验证 |
| --- | --- | --- |
| FR1 画像 | 用户填写、时区校验、可修正，来源不推测 | API 与浏览器 |
| FR2 目标澄清 | 目标/基础/预算/成果条件必填，未知可明示，路线确认 | domain + 浏览器 |
| FR3 资料检索 | Exa 真实结果、来源白名单核对，缺配置不造来源 | DSH 工具隔离；真实检索待凭据验收 |
| FR4 路线 | 版本、确认、当前阶段、固定最终条件、标准引用 | domain + API |
| FR5 行动 | 排程、冲突、暂停/恢复、取消、过期、投入 | domain + 浏览器 |
| FR6 练习 | 文字反馈、证据类型、原文引用、失败重试、已审核选择题确定性判分 | API + domain；题目由运营随公共标准发布 |
| FR7 挑战 | 独立成果、固定标准、三种结论、公共成就 | domain + 浏览器；真实评分质量待验收 |
| FR8 调整 | 原因、草案、显式确认、旧路线历史、已完成前缀保留 | domain |
| FR9 生命周期 | 暂停/恢复/结束、完成、外部结果待核实及运营入口 | domain + API |
| FR10 成长 | 版本化确定性规则、事务账本、重复请求去重 | domain + PostgreSQL 并发集成 |
| FR11 生活事件 | 手动输入、来源 ID 去重、机会双期限、不重复奖励 | domain；未连接外部日历 |

| FR13 管家 | 真实上下文、建议不自动执行、确认走正常命令 | DSH 协议 + 浏览器 |
| FR14 一致性 | 会话隔离、版本冲突、幂等回放、队列租约、取消、时区、导出 | API 并发、恢复与越权验证 |

## 自动验证

- `npm test`：目标确认与过时结果、调整保留、挑战证据、外部结果、XP 上限及唯一投入、时间冲突/过期、事件双期限、输入校验。
- `npm run test:integration`：真实 PostgreSQL/Redis、两个账号、并发重复请求、幂等键误用、过时版本、模型失败与重试、租约超时、取消、缓存版本、注销。
- 同一集成套件使用正式 DSH SDK + 本地 Messages SSE 端点，真实执行工具调用，断言工具只有 3 个业务工具，无终端工具。
- `npm run test:e2e`：真实浏览器与 HTTP、数据库和 worker；模型夹具固定，覆盖手机完整成长流程、刷新持久化、记忆修正及管家。桌面与手机截图留在 test-results（不提交）。

## 上线前须以真实配置验证

配置 DeepSeek 和可选 Exa 凭据后，以多个真实目标检查路线可行性、资料质量、诚实说明缺口、评估误判和模型提示注入；检查超时与费用。自动夹具验证程序约束，不验证真实模型能力。需要音视频评估、更丰富题型、外部日历、邮件找回、第三方登录或支付时，应补充明确需求和相应接口，当前 UI 不承诺这些能力。

仓库提交、GitHub push、CI、真实模型验收和线上发布是不同状态。此次实现不自动替换公开 Sites 演示或宣称生产验收完成。
